# 电商公司档案模板（服装零售）

首次为一家电商公司服务时，把下面信息问全，落到工作目录 `ecom-profile.md` + 三份 JSON（分别给三个脚本用）。

## 一、基本信息

| 字段 | 示例 | 为什么重要 |
|---|---|---|
| 公司/店铺名称 | 某某服饰旗舰店 | 报告抬头 |
| 经营主体 | 有限公司 / 个体户 / 多个主体 | 税务身份与拆分合规 |
| 平台与店铺 | 拼多多 2 店 + 淘宝 1 店 | 费率、账期、退货政策不同 |
| 品类 | 卫衣、内衣 | 退货率、季节性、毛利率基准 |
| 纳税人身份 | 小规模 / 一般纳税人 | 增值税算法 |
| 申报周期 | 按季 / 按月 | 申报日历 |
| 征收方式 | 查账征收 / 核定征收 | 所得税算法 |
| 年 GMV（含税） | 420 万 | 500 万临界点测算 |
| 员工人数 | 5（含客服/打包） | 小微判定、人工成本 |
| 仓库 | 自仓 / 云仓 / 一件代发 | 库存与履约成本 |

## 二、平台与经济参数

| 字段 | 示例 | 从哪拿 |
|---|---|---|
| 平台佣金/软件服务费 | 拼多多 0.6%；淘宝 C 店 0.6%；天猫服饰 5%+0.6% 基础软件服务费 | 平台规则中心 / 账单 |
| 结算账期 | 拼多多 17–19 天；淘宝/天猫 10–25 天；京东 T+1；抖音 4–30 天 | 平台结算规则 + 用自己 3 个月账单回算 |
| 保证金 | 0.5 万–10 万（按类目/店铺类型） | 平台后台 |
| 退货率 | 女装货架 50%–60%，直播 70%–85%（内衣通常更低，用自身数据） | 生意参谋/多多情报通/售后报表 |
| 快递单均 | 3.5–5 元（含偏远） | 快递月结单 |
| 包材单均 | 1–2 元 | 采购单 |
| 投流费比（占确收） | 10%–30% | 推广后台 |
| 达人佣金 | 20%–30%；达播费比 ≥35% | 合作合同 |
| 退货损耗 | 回程运费 + 折价 + 已结算不退的佣金 | 售后报表 + 平台规则 |

## 三、三份 JSON 的用途

### 1) 月度财务体检（`scripts/checkup.py`）
结构见 `assets/company-profile.md`。电商场景注意：
- `period.quarter_sales_excl_tax` 填**平台后台的季度成交额（不含税、扣退货后）**，不是开票额。
- `pl.revenue_excl_tax` 用净 GMV 换算，不用 GMV。

### 2) 税负身份对比（`scripts/tax_mode_compare.py`）
```json
{
  "company": {"name": "店铺名"},
  "year": {
    "gmv_incl_tax": 4200000,
    "return_rate": 0.25,
    "platform_fee_rate": 0.006,
    "logistics_rate": 0.06,
    "ad_rate": 0.15,
    "labor_rent": 250000,
    "purchase_cost_rate": 0.35,
    "invoice_ratio": 0.0,
    "extra_cost_rate": 0.05,
    "small_scale_rate": 0.01,
    "general_rate": 0.13,
    "city_tax_rate": 0.07,
    "surcharge_half": true,
    "cit_rate": 0.05
  }
}
```
- `invoice_ratio` 是**能拿到增值税专用发票的采购占比**——整个决策的核心变量，不知道就先填 0 跑一遍，再按实际调整。
- `purchase_cost_rate` 是采购成本占净 GMV 的比例。

### 3) 单元经济（`scripts/ecom_unit_econ.py`）
```json
{
  "company": {"name": "店铺名", "category": "卫衣/内衣"},
  "assumptions": {
    "platform_fee_rate": 0.006,
    "logistics_per_order": 4.5,
    "packaging_per_order": 1.5,
    "return_shipping_per_return": 6,
    "influencer_rate": 0,
    "ad_spend": 60000,
    "tax_rate": 0.01
  },
  "skus": [
    {"name": "加绒卫衣 A", "price_incl_tax": 129, "cost_incl_tax": 45,
     "return_rate": 0.25, "monthly_orders": 1200, "stock": 800, "sales_last_30d": 1200}
  ]
}
```
- 每个 SKU 至少给：售价、成本、退货率、月订单量、库存、近 30 天销量。
- 不会算就先用后台的"商品效果"报表导 10 个主推款。

## 四、取数清单（电商专用）

| 数据 | 来源 | 用途 |
|---|---|---|
| 成交额 / 退款额（按月） | 各平台后台"交易分析""售后分析" | GMV→收入桥、退货率 |
| 平台账单（结算明细） | 平台"资金/结算"页导出 | 对账、实际到账 |
| 推广费明细 | 直通车/千川/多多搜索后台 | 投流 ROI |
| 快递月结单 | 快递公司 | 履约成本 |
| 采购付款记录 | 微信/支付宝/银行流水 + 档口收据 | 成本台账（无票也要记） |
| 库存表 | 自仓盘点/云仓后台 | 库存周转、跌价 |
| 工资表 | 内部 | 人工成本、个税 |
| 已开票/受票记录 | 电子税务局 | 收入与进项核对 |

> 无票采购也要建内部台账（日期、供应商、品名、数量、单价、付款凭证），这是证明成本真实性的唯一底稿；没有它，税务上成本不能扣除。
